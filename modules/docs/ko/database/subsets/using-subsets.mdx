Subset은 Model의 메서드를 통해 사용합니다.

## Model 메서드와 Subset

### findById - 단일 레코드 조회

```typescript
// Subset 1개
const user = await UserModel.findById(1, ["P"]);
// 타입: UserSubsetMapping["P"]

// Subset 여러 개 (Union)
const user = await UserModel.findById(1, ["A", "P"]);
// 타입: UserSubsetMapping["A"] | UserSubsetMapping["P"]
```

### findOne - 조건으로 단일 레코드

```typescript
const user = await UserModel.findOne({
  where: [["email", "john@test.com"]],
  subsetKey: "P",
});
// 타입: UserSubsetMapping["P"] | undefined
```

### findMany - 여러 레코드 조회

```typescript
const users = await UserModel.findMany({
  listParams: {
    page: 1,
    pageSize: 20,
  },
  subsetKey: "L",
});
// 타입: UserSubsetMapping["L"][]
```

## getPuri로 Subset 쿼리 시작

`getPuri`를 사용하여 Subset 기반 쿼리를 시작합니다:

```typescript
// Subset P의 쿼리 시작
const query = UserModel.getPuri("r", ["P"]);

// 추가 조건 적용
const users = await query
  .where("users.role", "admin")
  .where("users.is_verified", true)
  .orderBy("users.created_at", "desc");

// 타입: UserSubsetMapping["P"][]
```

<Info>
`getPuri("r", ["P"])`는 Subset P에 정의된 JOIN과 SELECT를 자동으로 적용합니다.
</Info>

## Subset 쿼리 확장

### WHERE 조건 추가

```typescript
const admins = await UserModel.getPuri("r", ["L"])
  .where("users.role", "admin")
  .where("users.is_verified", true);

// Subset L의 기본 필드 + WHERE 조건
```

### ORDER BY 정렬

```typescript
const recentUsers = await UserModel.getPuri("r", ["L"])
  .orderBy("users.created_at", "desc")
  .limit(10);
```

### 복합 조건

```typescript
const activeEngineers = await UserModel.getPuri("r", ["P"])
  .where("users.role", "normal")
  .where("employee__department.name", "Engineering")
  .where("employee.salary", ">", "60000")
  .orderBy("employee.salary", "desc");

// Subset P는 employee.department.name을 포함하므로
// JOIN이 자동으로 설정됨
```

## Subset 타입 안전성

### 컴파일 타임 검증

```typescript
// ✅ OK: Subset P는 employee__department 테이블 포함
await UserModel.getPuri("r", ["P"])
  .where("employee__department.name", "Engineering");

// ❌ Type Error: Subset L은 employee 테이블 미포함
await UserModel.getPuri("r", ["L"])
  .where("employee__department.name", "Engineering");
//     ^^^^^^^^^^^^^^^^^^^^^^^^^ Property does not exist
```

### 자동 타입 추론

```typescript
const user = await UserModel.findById(1, ["P"]);

// TypeScript가 자동으로 타입 추론
user.id;        // number
user.username;  // string
user.employee;  // { salary: string; department: { name: string } } | null

// ❌ Compile Error
user.password;  // Property 'password' does not exist
```

### Subset 교집합 (Multiple Subsets)

여러 Subset을 동시에 지정하면, TypeScript는 **교집합 타입**을 자동으로 계산합니다.

#### 기본 교집합

```typescript
// Subset A와 P의 교집합
const user = await UserModel.findById(1, ["A", "P"]);

// 타입: 두 Subset에 공통으로 있는 필드만 사용 가능
user.id;        // ✅ OK (A, P 모두 포함)
user.username;  // ✅ OK (A, P 모두 포함)
user.email;     // ✅ OK (A, P 모두 포함)

user.employee;  // ❌ Type Error (A에는 없음, P에만 있음)
user.bio;       // ❌ Type Error (P에는 없음, A에만 있음)
```

**교집합이 동작하는 이유**:
- `["A", "P"]`는 Union이 아닌 **Intersection** 타입을 생성
- 런타임에는 두 Subset 중 **더 큰 Subset**의 데이터가 반환됨
- 하지만 타입 시스템은 **공통 필드만 보장**

#### 쿼리에서의 교집합

```typescript
// 쿼리 시작: A와 P 교집합
const query = UserModel.getPuri("r", ["A", "P"]);

// ✅ OK: 공통 필드만 WHERE 조건 가능
await query.where("users.username", "like", "%john%");
await query.where("users.email", "john@example.com");

// ❌ Type Error: employee는 교집합에 없음
await query.where("employee__department.name", "Engineering");
//                ^^^^^^^^^^^^^^^^^^^^^^^^^ Property does not exist
```

#### 실전 예제: 조건부 Subset 선택

```typescript
async getUserData(userId: number, includeEmployeeInfo: boolean) {
  // 조건에 따라 Subset 선택
  const subsets = includeEmployeeInfo ? ["P"] : ["A"];

  const user = await UserModel.findById(userId, subsets);

  // TypeScript 타입:
  // - includeEmployeeInfo가 true면: UserSubsetMapping["P"]
  // - includeEmployeeInfo가 false면: UserSubsetMapping["A"]
  // - 하지만 변수 subsets의 타입이 ["P"] | ["A"]이므로
  //   실제로는 교집합 타입이 추론됨

  return {
    id: user.id,
    username: user.username,
    email: user.email,
    // employee 필드는 타입 체크 통과 안됨 (교집합에 없음)
  };
}
```

**교집합 우회 방법**:

```typescript
// 방법 1: 타입 가드 사용
async getUserDataWithGuard(userId: number, includeEmployeeInfo: boolean) {
  if (includeEmployeeInfo) {
    const user = await UserModel.findById(userId, ["P"]);
    // 여기서 user는 UserSubsetMapping["P"] 타입
    return {
      ...user,
      department: user.employee?.department?.name,
    };
  } else {
    const user = await UserModel.findById(userId, ["A"]);
    // 여기서 user는 UserSubsetMapping["A"] 타입
    return user;
  }
}

// 방법 2: 제네릭 사용
async getUserDataGeneric<T extends UserSubsetKey>(
  userId: number,
  subset: T
): Promise<UserSubsetMapping[T]> {
  const user = await UserModel.findById(userId, [subset]);
  return user;
}

// 사용
const userA = await getUserDataGeneric(1, "A");  // 타입: UserSubsetMapping["A"]
const userP = await getUserDataGeneric(1, "P");  // 타입: UserSubsetMapping["P"]
```

#### onSubset 메서드와 교집합

`onSubset` 메서드로 Subset 조건을 동적으로 적용할 때도 교집합이 계산됩니다:

```typescript
const query = UserModel.getPuri("r", ["A"]);

// Subset A와 P 조건 모두 적용
const result = await query
  .onSubset(["A", "P"], (qb) => {
    // 이 블록 내에서는 A와 P의 교집합 필드만 사용 가능
    qb.where("users.username", "like", "%john%");  // ✅ OK

    // ❌ Type Error: employee는 교집합에 없음
    // qb.where("employee__department.name", "Engineering");
  });
```

**onSubset의 타입 추론**:

```typescript
// 단일 Subset
query.onSubset(["A"], (qb) => {
  // qb는 Subset A의 모든 필드 사용 가능
});

// 복수 Subset (교집합)
query.onSubset(["A", "P"], (qb) => {
  // qb는 A와 P의 교집합 필드만 사용 가능
});

// 교집합이 비어있으면?
query.onSubset(["L", "P"], (qb) => {
  // L과 P의 공통 필드만 사용 가능
  // 만약 공통 필드가 거의 없다면, 사용 가능한 필드가 매우 제한적
});
```

<Warning>
**교집합 사용 시 주의사항**:
1. **런타임 데이터 ≠ 타입**: 런타임에는 더 큰 Subset의 모든 필드가 반환되지만, 타입 시스템은 교집합만 보장
2. **의도하지 않은 교집합**: 여러 Subset을 배열로 전달할 때 실수로 교집합이 발생할 수 있음
3. **타입 가드 권장**: 조건부로 Subset을 선택할 때는 타입 가드를 사용하여 정확한 타입 추론
</Warning>

<Info>
**언제 교집합을 사용하나요?**
- 여러 API에서 공통으로 필요한 필드만 조회할 때
- 타입 안전성을 극대화하고 싶을 때
- 불필요한 필드 노출을 방지하고 싶을 때

대부분의 경우 **단일 Subset** 사용을 권장합니다.
</Info>

## 실전 예제

### 사용자 목록 API

```typescript
// Controller
class UserController {
  async list(req: TypedRequest<UserListParams>) {
    const { page, pageSize, role, search } = req.body;
    
    let query = UserModel.getPuri("r", ["L"]);
    
    // 역할 필터
    if (role) {
      query = query.where("users.role", role);
    }
    
    // 검색
    if (search) {
      query = query.where("users.username", "like", `%${search}%`);
    }
    
    const users = await query
      .orderBy("users.created_at", "desc")
      .limit(pageSize)
      .offset((page - 1) * pageSize);
    
    return users;
  }
}
```

### 프로필 조회 API

```typescript
async getProfile(userId: number) {
  const user = await UserModel.findById(userId, ["P"]);
  
  if (!user) {
    throw new NotFoundException("User not found");
  }
  
  return {
    id: user.id,
    username: user.username,
    email: user.email,
    bio: user.bio,
    department: user.employee?.department?.name,
    salary: user.employee?.salary,
  };
}
```

### 복합 검색 API

```typescript
async searchUsers(params: {
  role?: UserRole;
  departmentName?: string;
  minSalary?: number;
}) {
  let query = UserModel.getPuri("r", ["P"]);
  
  if (params.role) {
    query = query.where("users.role", params.role);
  }
  
  if (params.departmentName) {
    query = query.where(
      "employee__department.name",
      "like",
      `%${params.departmentName}%`
    );
  }
  
  if (params.minSalary) {
    query = query.where("employee.salary", ">=", String(params.minSalary));
  }
  
  return await query.orderBy("users.username", "asc");
}
```

## Subset 조합

### 여러 Subset 사용 (Union)

```typescript
// 상황에 따라 다른 Subset 사용
async getUser(userId: number, detailed: boolean) {
  if (detailed) {
    return await UserModel.findById(userId, ["P"]);
    // 타입: UserSubsetMapping["P"] | undefined
  } else {
    return await UserModel.findById(userId, ["SS"]);
    // 타입: UserSubsetMapping["SS"] | undefined
  }
}
```

### 조건부 Subset 선택

```typescript
async getUserData(userId: number, role: UserRole) {
  const subsets = role === "admin" ? ["A"] : ["P"];
  
  return await UserModel.findById(userId, subsets);
  // 타입: UserSubsetMapping["A"] | UserSubsetMapping["P"] | undefined
}
```

## 성능 최적화

### 필요한 Subset만 사용

```typescript
// ❌ 나쁨: 목록에서 Subset A 사용 (과도한 데이터)
const users = await UserModel.findMany({
  listParams: { page: 1, pageSize: 20 },
  subsetKey: "A",  // 모든 필드 로딩
});

// ✅ 좋음: 목록에는 Subset L 사용
const users = await UserModel.findMany({
  listParams: { page: 1, pageSize: 20 },
  subsetKey: "L",  // 필요한 필드만
});
```

### JOIN 최소화

```typescript
// ❌ 나쁨: 불필요한 JOIN (Subset P)
const userIds = await UserModel.getPuri("r", ["P"])
  .pluck("users.id");
// employee, department 테이블도 JOIN됨

// ✅ 좋음: JOIN 없는 Subset (SS)
const userIds = await UserModel.getPuri("r", ["SS"])
  .pluck("users.id");
// users 테이블만 조회
```

## Subset과 Raw Puri 비교

### Subset 사용

```typescript
// ✅ Subset - 타입 안전, 간결
const users = await UserModel.getPuri("r", ["P"])
  .where("users.role", "admin");

// 타입: UserSubsetMapping["P"][]
// JOIN 자동 설정
// SELECT 자동 설정
```

### Raw Puri 사용

```typescript
// ⚠️ Raw Puri - 수동 설정
const users = await UserModel.getPuri("r")
  .table("users")
  .leftJoin("employees", "users.id", "employees.user_id")
  .leftJoin("departments", "employees.department_id", "departments.id")
  .select({
    id: "users.id",
    username: "users.username",
    employee__salary: "employees.salary",
    employee__department__name: "departments.name",
  })
  .where("users.role", "admin");

// 타입: { id: number; username: string; ... }[]
// JOIN 수동 설정
// SELECT 수동 설정
// Hydrate 수동 적용 필요
```

</Tip>

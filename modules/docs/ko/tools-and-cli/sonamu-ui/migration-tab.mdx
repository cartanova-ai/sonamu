Migration 탭은 Entity와 데이터베이스 스키마의 차이를 비교하고, 마이그레이션 파일을 생성하거나 여러 데이터베이스에 적용하는 화면입니다.

## 비교·생성

**기준 DB**에는 모든 마이그레이션이 적용된 연결만 나타납니다. Sonamu는 이 데이터베이스의 실제 스키마를 Entity 정의와 비교해 생성할 변경사항과 코드를 보여줍니다.

1. 기준 DB를 선택합니다.
2. 필요하면 **모두 펼치기**로 생성 코드를 검토합니다.
3. **마이그레이션 생성**을 눌러 파일을 만듭니다.

파일 생성 후에는 모든 데이터베이스의 Pending 상태가 다시 계산됩니다.

## 마이그레이션 상태

행은 마이그레이션 파일, 열은 데이터베이스 연결입니다. 각 셀은 `APPLIED` 또는 `PENDING`을 표시합니다. 연결은 각각 독립적으로 조회되므로 느리거나 실패한 데이터베이스가 다른 열의 표시를 막지 않습니다.

- 열 머리글이나 셀을 눌러 실행 대상을 선택합니다.
- **자세히**를 켜면 host, database, remote 여부와 열 새로고침 버튼을 볼 수 있습니다.
- 연결 오류의 **오류** 배지를 누르면 서버가 반환한 원인을 확인할 수 있습니다.

## 최신으로 적용

**최신으로 적용**은 선택한 데이터베이스에 대해 `knex.migrate.latest()`를 순서대로 실행합니다. 한 데이터베이스에서 적용되는 파일은 하나의 Knex batch를 유지합니다.

실행 창은 다음 순서로 진행됩니다.

1. **검토**: 대상과 Pending 파일을 확인하고 Shadow 검증 여부를 선택합니다.
2. **승인**: 설정된 원격 대상이 있으면 Slack 승인을 요청하고 2초마다 상태를 확인합니다.
3. **적용**: 파일별 실행 진행률과 데이터베이스별 완료 상태를 표시합니다.

Shadow를 켜면 점선 Shadow 검증 카드가 대상 목록 맨 위에 표시됩니다. 적용을 시작하면 같은 카드가 실제 검증 진행률과 결과를 보여주며, Shadow 검증이 성공한 경우에만 실제 대상 적용을 시작합니다.

<Warning>
  파일별 `실행됨` 표시는 해당 migration 함수가 끝났다는 뜻입니다. 전체 batch가 확정된 것은 데이터베이스 카드가 완료된 뒤입니다.
</Warning>

브라우저 연결이 끊겨도 서버에서 시작한 migration은 계속될 수 있습니다. 자동으로 다시 실행하지 말고 상태를 새로고침해 실제 결과를 확인하세요.

## 롤백

Rollback은 파일 행 선택과 무관하게, 선택한 각 데이터베이스의 **가장 최근 Knex batch 전체**를 되돌립니다. `down()`은 Knex가 제공한 역순으로 실행됩니다.

파괴적인 동작이므로 롤백 버튼을 처음 누르면 확인 문구로 바뀌고, 한 번 더 눌러야 실행됩니다. 도중에 오류가 발생하면 해당 파일에서 중단됩니다. 다만 롤백 트랜잭션도 취소되기 때문에 아무런 변화가 없어 보일 수 있습니다. 롤백은 최신 마이그레이션부터 순서대로 실행되므로, 이렇게 중간에 문제가 발생하는 경우 다음 롤백으로 넘어갈 수 없습니다.

<Warning>
  롤백은 컬럼이나 테이블을 삭제해 데이터를 유실할 수 있습니다. Production에서는 백업과 `down()` 구현을 먼저 확인하세요.
</Warning>

# miomock 기획서

## 1. 프로젝트 배경

중소규모 기업에서 조직 구조, 인력 배치, 프로젝트 진행 상황을 하나의 플랫폼에서 관리하고 싶다는 니즈가 있다. 현재는 조직도를 스프레드시트로, 프로젝트를 별도 도구로, 문서를 또 다른 시스템으로 관리하고 있어 정보가 분산되어 있다.

miomock은 **조직 관리 + 프로젝트 관리 + 문서 관리**를 하나로 통합한 사내 플랫폼이다.

## 2. 목표 사용자

### 일반 직원
- 자기 프로필을 관리한다.
- 배정된 프로젝트를 확인한다.
- 문서를 작성하고 검색한다.
- 파일을 업로드한다.

### 관리자 (HR/운영팀)
- 회사, 부서, 직원 정보를 등록하고 관리한다.
- 프로젝트를 생성하고 인력을 배정한다.
- 불필요한 데이터를 삭제한다.

### 시스템 관리자
- 사용자 계정을 관리한다.
- 보안 정책(2단계 인증 등)을 설정한다.

## 3. 핵심 도메인

### 3.1 사용자 및 인증

사용자는 이메일로 가입하고, 비밀번호로 로그인한다.

**가입 흐름:**
- 이메일 + 비밀번호 + 이름으로 가입
- 가입 후 이메일 검증 메일 발송
- 이메일 검증을 완료해야 정식 사용자로 전환
- 검증 링크는 일정 기간 후 만료됨

**로그인 흐름:**
- 이메일 + 비밀번호로 로그인
- 로그인 성공 시 세션 생성 (1년간 유지)
- 로그인 시점의 IP와 접속 환경을 기록
- Google, GitHub 등 외부 계정으로도 로그인 가능

**보안 강화:**
- 패스키(지문/얼굴 인식)를 등록하면 비밀번호 없이 로그인 가능
- 2단계 인증(OTP 앱)을 활성화하면 로그인 시 추가 코드 입력 필요
- 2단계 인증 활성화 시 비상용 백업 코드 발급

**사용자 프로필:**
- 이름, 생년월일, 자기소개, 프로필 이미지
- 프로필은 본인이 수정 가능

**계정 삭제:**
- 관리자만 삭제 가능
- 삭제된 계정은 즉시 파기되지 않고 비활성 상태로 보관 (복구 가능성)
- 삭제된 계정의 이메일로 재가입은 불가

**역할:**
- 일반 사용자: 조회, 생성, 수정 가능
- 관리자: 일반 사용자 권한 + 삭제 권한

### 3.2 조직 관리

#### 회사
- 여러 회사를 등록할 수 있다 (멀티 테넌트 아님, 관리 대상으로서의 회사 목록).
- 회사 이름은 중복 불가.
- 회사를 삭제하면 소속 부서가 전부 삭제된다.

#### 부서
- 회사 아래에 부서를 만든다.
- 부서는 상하 관계를 가질 수 있다 (예: 개발본부 > 백엔드팀 > 서버파트).
- 같은 회사 안에서 부서 이름은 중복 불가.
- 부서 코드는 자동 부여된다 (DEP-001, DEP-002, ...).
- 부서별 소속 직원 수를 확인할 수 있다.
- 부서를 삭제하면:
  - 하위 부서도 함께 삭제된다.
  - 소속 직원은 삭제되지 않고 "미배치" 상태가 된다.

#### 직원
- 가입된 사용자를 직원으로 등록한다.
- 직원 등록 시 사번을 부여한다.
- 한 사용자는 하나의 직원 레코드만 가질 수 있다 (중복 등록 불가).
- 직원을 부서에 배치하거나, 배치하지 않을 수 있다 (미배치 허용).
- 급여와 입사일을 기록한다.
- 직원은 여러 프로젝트에 참여할 수 있다.

### 3.3 프로젝트 관리

- 프로젝트는 이름, 설명, 예산, 마감일을 가진다.
- 프로젝트 상태: 기획 중 → 진행 중 → 완료 또는 취소.
- 프로젝트에 직원을 배정한다 (여러 명 가능).
- 프로젝트에 태그를 붙여 분류한다 (여러 개 가능).
- 프로젝트 저장 시 배정 인원이나 태그가 변경되면, 해제된 항목은 즉시 반영된다.
- 프로젝트 이름과 설명으로 전문 검색이 가능하다.
- 이미지를 첨부할 수 있다 (여러 장).
- AI 어시스턴트에게 프로젝트 관련 질문을 할 수 있다 (실시간 답변).

### 3.4 문서 관리

- 제목과 본문으로 문서를 작성한다.
- 문서 상태: 초안 → 게시 → 보관.
- 문서 내용을 기반으로 의미 검색이 가능하다 (키워드 일치가 아닌, 의미가 비슷한 문서를 찾아줌).

### 3.5 태그

- 태그를 만들어 프로젝트를 분류한다.
- 태그 이름은 한국어, 영어, 일본어를 지원한다.
- 태그 목록은 자주 조회되므로 빠른 응답이 필요하다.

### 3.6 파일

- 시스템에 파일을 업로드한다.
- 한 번에 최대 10개까지 업로드 가능.
- 같은 파일을 중복 업로드하면 감지한다.
- 파일 크기 제한: 30MB.

## 4. 데이터 간 관계

```
회사
└── 부서 (계층 구조)
    └── 직원 ←→ 사용자 (1:1)
        └── 프로젝트 참여 (다대다)
            ├── 태그 분류 (다대다)
            └── 이미지 첨부

문서 (독립)
파일 (독립)
```

- 회사 삭제 → 부서 전체 삭제 → 직원은 "미배치"로 전환 (삭제 아님)
- 사용자 삭제 → 인증 관련 데이터(세션, 패스키, 2FA) 전체 삭제
- 프로젝트와 직원/태그는 다대다 관계

## 5. 주요 제약사항

### 고유성
- 사용자 이메일: 시스템 전체에서 유일
- 회사 이름: 시스템 전체에서 유일
- 부서 이름: 같은 회사 안에서 유일
- 파일 URL: 시스템 전체에서 유일

### 삭제 정책
- 모든 삭제는 관리자만 가능
- 사용자 삭제는 soft delete (데이터 보존)
- 회사/부서 삭제는 hard delete + 연쇄 삭제
- 부서 삭제 시 직원은 삭제하지 않고 미배치 처리

### 인증 정책
- 세션 유효 기간: 1년
- 이메일 검증 토큰: 만료 기간 있음
- 2FA 백업 코드 소진 시 자체 복구 불가 (관리자 개입 필요)
- 삭제된 계정의 이메일로 재가입 불가

### 목록 조회
- 기본 페이지 크기: 24건
- 전체 조회 가능 (페이지 크기 0 지정 시)
- 응답에는 전체 건수, 현재 페이지, 전체 페이지 수를 포함

## 6. 다국어 지원

- 시스템 기본 언어: 한국어
- 지원 언어: 한국어, 영어, 일본어
- 현재 다국어 적용 대상: 태그 이름

## 7. 향후 고려사항

아래는 현재 범위에 포함되지 않으나, 추후 논의가 필요한 항목이다.

- **알림 시스템**: 프로젝트 배정, 마감일 임박, 문서 상태 변경 시 알림
- **권한 세분화**: 현재 일반/관리자 2단계 → 부서별 관리자, 프로젝트별 권한 등으로 확장
- **감사 로그**: 누가 언제 어떤 데이터를 변경했는지 이력 관리
- **문서 버전 관리**: 문서 수정 이력 추적, 이전 버전 복원
- **프로젝트 타임라인**: 간트 차트, 마일스톤, 일정 관리
- **대시보드**: 조직 현황, 프로젝트 진행률, 인력 배치 현황 시각화
- **직원 직급/직책 관리**: 직급 체계 정의, 직급별 급여 테이블
- **회사 간 데이터 격리**: 현재 모든 데이터가 공유됨, 회사별 접근 제어 필요 여부 결정
